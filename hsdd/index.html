The spec is the program.

HSDD scales spec-driven development from a single spec to large, multi-team systems: recursive decomposition, first-class contracts, and one human-reviewed phase at a time.

Start the interactive guide → Read the user's guide Install

Why HSDD

One spec stops scaling. A tree of small ones does not.

Single-spec workflows work well for small systems. As the system grows, the one spec becomes too large, every session re-reads all of it, and model focus degrades. HSDD decomposes the spec the way you would decompose the program.

The unit of spec-driven development is not the product. It is the smallest independently verifiable phase with explicit contracts.

✓

Human review is the pacing unit

Agents produce faster than people can read. Every phase is sized to one review sitting, one Phase Equivalent, and done means a verification doc a human signed.

⌥

Modularity in the spec

The spec is a tree of nodes coupled only through named, versioned contracts, split where ownership splits, with a typed dependency graph in place of whole-spec coupling.

ƒ

A functional model underneath

Each node is a function from the contracts it consumes to the contracts it produces. The dependency graph is the composition; internals stay private.

▢

Bounded context per session

A phase's session gets its phase, the contracts it touches and the decisions that govern it. Per-session context tracks the phase, not the system; the total still grows with phase count.

How it works

Two ways in, one shared loop

Greenfield starts from an idea and decomposes. Brownfield starts from a codebase and adopts it shallowly. From then on every change enters through intake into the same tree: the tree does not complete, phases complete.

GreenfieldA brain-dump, PRD or RFC goes to hsdd-spec, which decomposes the system into nodes until each is small enough to phase.
Brownfieldhsdd-adopt extracts the seams by script, writes an as-built tree with v0 contracts that describe current behavior, and stops.
Every later changehsdd-intake routes a PRD, RFC, ticket or incident into the existing tree. A PRD is never a root.
  1. DecomposeSplit the system into a tree of nodes with hsdd-spec; cross-cutting decisions become ADRs.
  2. ContractEvery boundary is a versioned file with a schema or fixtures (hsdd-contract).
  3. Phase-planEach leaf-parent becomes ordered phases with gates and review tiers (hsdd-phase-plan).
  4. ReconcileDrain the pending governance updates at the root (hsdd-reconcile).
  5. Configure and buildOne phase context (hsdd-config), then one coding cycle, OpenSpec or superpowers.
  6. ReviewA human reads the diff and runs the verification at the phase's tier, then signs.

hsdd-auto runs steps 1 to 4, and intake handoffs, unattended: one fresh subagent per skill invocation, every step gated and committed, every decision recorded for one review sitting. It never implements a phase or passes a review gate. Once implementation starts, hsdd-checkpoint runs the weekly evidence pass and hsdd-milestone keeps the stakeholder dates.

Install

Thirteen skills, one command

HSDD ships as agent skills, installable with the skills CLI, which works with Claude Code, Cursor, Codex and 70+ other agents.

bash
# All thirteen HSDD skills
npx skills add mpurbo/hsdd

# Or a single skill
npx skills add mpurbo/hsdd --skill hsdd-spec

Recommended companion: Obra's superpowers plugin. HSDD composes with its test-driven development, verification and code-review skills instead of re-implementing them, and hsdd-config wires them into each phase's coding session.

Slash commands are optional and not installed by the CLI: copy commands/*.md into your project's .claude/commands/.

Then follow Example 1 of the user's guide, or the first tutorial.

first prompts
"Write a high-level spec for a merchant onboarding platform."      -> hsdd-spec (root)
"Break down @hsdd/spec/acme.md into backend, mobile, and web."     -> hsdd-spec (internal node)
"Define the auth-token contract: auth produces, billing consumes." -> hsdd-contract
"Write the ADR for the auth provider decision."                    -> hsdd-adr
"acme.backend.auth is small enough. Write its phase plan."         -> hsdd-phase-plan
"Reconcile the worktrees."                                         -> hsdd-reconcile
"/hsdd-phase acme.backend.auth.2"   (switch the phase context, then run the cycle)
"/hsdd-auto"                        (plan the tree unattended, review the ledger after)

The skill set

What each skill is for

Each skill owns one step of the method and writes one kind of artifact. The reference has the full entry for each.

Build the tree

hsdd-specTurn a brain-dump into a high-level spec, or decompose any node into child nodes.hsdd-contractDefine and version the first-class contracts between nodes.hsdd-adrAuthor and maintain cross-cutting Architecture Decision Records as first-class files, with registry-compatible frontmatter and a status lifecycle.

Plan the phases

hsdd-phase-planBreak a small-enough node into ordered, independently implementable phases, each sized for one coding cycle and one review window.hsdd-reconcileDrain the pending governance updates emitted by phase planning: finalize contract phase ids, resolve contract-gap requests with you, and regenerate the registries.

Execute a phase

hsdd-configBefore each phase, write one self-contained phase context (the phase, the text of the contracts it touches, its decisions, pinned links) and wrap it for the project's coding method: OpenSpec's config.yaml, or a spec for superpowers' writing-plans.

Existing systems and change

hsdd-adoptBring an existing codebase into the tree: script-extracted seams, as-built node specs with an ## Observed surface section, and v0 contracts describing current behavior.hsdd-intakeRequest mode: classify an incoming change request (PRD, RFC, ticket, incident), detect collisions with open intakes, route it into the existing tree, write the routing record and hand off; answer a request below the line with a node and a trailer.hsdd-sealSeal a released tree whose artifacts went stale, by script and with no model in the loop: a plan with a default class per phase, the owner's edit of that class, then retroactive verification docs by delegated sign-off, Status: dropped on unbuilt phases, pruned catch-up OpenSpec directories, closed intake records and the campaign document sealed into the archive.

Run the project

hsdd-checkpointRun the weekly (or context-triggered) evidence pass across the spec repo and every implementation repo, emitting a progress report, a revised execution plan, a regenerated atlas, and ticked milestone gates.hsdd-milestoneGenerate a campaign's stakeholder milestone document once every leaf-parent in its scope is phase-planned.hsdd-summaryRender offline HTML reading aids: the plan page (root to phase cards, for a reviewer, a stakeholder or an implementer) and the checkpoint page (the newest progress report and execution plan, for the lead running the sync, each lane's executor, and stakeholders).

Unattended

hsdd-autoRun HSDD's planning chain unattended: compute the next step, dispatch one fresh subagent per skill invocation, answer or stop on each ask point per the owner's stop policy, gate and commit each step, and record every decision for one review sitting.
