#[0.11.0] - Unreleased

Unattended planning runs. hsdd-auto runs HSDD's planning chain without the owner at each ask point, one fresh subagent per skill invocation, and records every decision for one review sitting afterwards.

Specification: spec/hsdd-spec-v0_11.md. Settled build decisions: docs/superpowers/plans/2026-10-22-hsdd-auto-decisions.md. Acceptance: review/hsdd-v0_11-acceptance.md.

#Upgrading from 0.10.2

  • Reinstall the twelve skills. Nothing else changes unless /hsdd-auto runs.
  • A project that never runs /hsdd-auto is unaffected: the new ## Unattended runs sections are inert unless a skill is invoked with --unattended.
  • A hsdd/judgement/decisions.jsonl written by a hand-built unattended run continues under hsdd-auto; its lines read as legacy lines, with one warning.

#Added

  • hsdd-auto, the twelfth skill, with bundled zero-dependency scripts (state, next, dispatch, decide, ledger, gate, commit, routed, report, adapter) copied verbatim to hsdd/scripts/auto/ by the first setup step. The scripts compute the next step, render its prompt, gate and commit it, mint and stamp every decision, and write the report; the orchestrator keeps the judgement.
  • Two modes. plan plans an empty tree through reconcile. intake routes one change request through hsdd-intake and every handoff its record names.
  • A stop policy per segment. stop ends the run with hsdd/judgement/STOP.md at a stop-set condition; decide-and-record decides it and records the decision with would_have_asked: true. A class can be decided in advance with predecided. external and four other hard stops end the run under either policy.
  • Run records: hsdd/auto/ (the run configuration, the plan, the queue, every dispatch file, step reports, one report per segment) and hsdd/judgement/ (the decision ledger, the run log, STOP.md, and the owner's decision-reviews.jsonl).
  • A Claude Code adapter (adapter.mjs install, adapter.mjs check): permission deny rules and a Bash hook that keep a run inside its declared inputs.
  • docs/guide/: chapter 10, "Run unattended", on handing planning to an agent and reviewing its decisions afterwards.
  • docs/tutorial/meeting-rooms/: a third recorded run, the first planned by hsdd-auto. PRD version 2 grows simple-login into meeting-room booking for two offices in different time zones, with PostgreSQL in Docker; an intake segment plans it unattended (31 steps, 231 recorded decisions, no stop), the owner's review follows in one sitting over the ledger, twelve phases are built in a backend, a web and an integration lane, and a checkpoint closes the intake. The template/, the execute/ repository with its full history, and an interactive walkthrough/ with the process log, including the findings about HSDD the run surfaced.
  • Test coverage: script tests for every script and test/auto-e2e.test.mjs, which drives the scripts through simulated plan, stop, procedural-stop, intake, rework and interruption runs.

#Changed

  • hsdd-spec, hsdd-adr, hsdd-contract, hsdd-phase-plan, hsdd-reconcile and hsdd-intake each gain an ## Unattended runs section: the skill's ask points as a table, a structured stop at an ask point instead of a question, and each decision recorded when it is taken.
  • hsdd-intake gains an optional machine-readable handoff block in the intake record; existing records stay conformant.
  • hsdd-reconcile gains a named align mode.
  • hsdd-contract, hsdd-adr and hsdd-spec gain the citation-touch rule for moving citations when a source document or contract version changes.
  • The contract file gains the optional front-matter field governed_by. Open-question and Collides with separators admit :, an en dash or - beside the em dash, and an empty cell admits none and -.

#Fixed

hsdd-auto was built against 0.10.0. Before the tutorial run, a check against 0.10.1 and 0.10.2 found fifteen gaps (build decisions B-40 to B-51), and the run itself showed six more defects (B-52 to B-57). All are fixed here; the 775 tests the branch had grew to 815.

  • Contracts are indexed by front-matter id, so a later version in its own file ({slug}.v{n}.md, 0.10.2) is the same contract: the gate's C4 and C5, the facts a step receives, the target lines, C3 and the ## Produced append all read the version a citation names.
  • approved-prd is an authority, rendered in hsdd-intake's words wherever it reaches a prompt or a record.
  • A lower contract version counts as superseded only when it is deprecated or retired; citation touch and align never edit a node header's Produces or Consumes or an ADR's affects, so a coexisting version keeps its live citations.
  • A bump's migration mode (coexisting or lockstep) has an unattended disposition under breaking-amend, and a predecided answer names it; hsdd-contract and hsdd-reconcile route the lockstep consumers' phases and the ADR affects update as inserted steps.
  • "Shipped" reads the conventions' **Main line:**, not origin/HEAD.
  • A baseline source's version matches only with its citation name, never as a bare token ("1" matched every minLength: 1).
  • An item on a handoff waits for that handoff's own step instead of being handed to every earlier step on the same node.
  • An inserted step's invocation carries its item's text; an accepted insert-step can be withdrawn while no step has run it.
  • ## Produced lists new contracts and proposed ADRs and drops its placeholder.
  • The parent's citation touch owns its copies of a child's lines.
  • v0.11 reads against v0.10.2; its "v0.10.0 §n" prefix names the v0_10 document as of 0.10.2.

The tutorial's process log lists eleven further findings about HSDD (hsdd-config's referenced-contract closure and self-contained check, the verification template, the superpowers derivative, sizing, evidence), left unchanged for the owner.

#Notes for the owner

The build found these errata in the specification and worked around them without editing it. The decisions file records each.

  • C.3 writes the contract step's G{n}, which section 13.2 reads as a slot named n; the template renders G{n} through G{{n}} (B-13).
  • Section 11.1 appends /** to every deny rule, which never matches a file path; the adapter writes the path itself and the path with /** (B-22).
  • D1 (prose rules) on run.yaml blocked every segment at level error, because the file lists the banned phrases and stores the owner's instruction verbatim; D1 exempts run.yaml, owner-files.json, adapter.json and the orchestrator_files (B-23).
  • C5's literal reading passes a citation of a contract version that does not exist yet, because the Versioning line names the next version; C5 accepts only the current version or an older one the section names (B-7).

#[0.9.0] - 2026-10-10 (never released; ships in 0.10.0)

Design: docs/superpowers/specs/2026-10-09-v0_9-phase-context-and-summaries-design.md.

Before each phase, hsdd-config writes hsdd-context/{phase-id}.md in the implementation repo: the phase, the Interface and Guarantees of every contract it consumes and produces, the Decision and Consequences of its ADRs, its open questions, and pinned links.   • Chapter 13, Reading Aids, in spec/hsdd-spec-v0_9.md.

  • hsdd-checkpoint: hsdd-context/ counts as in-progress evidence; when hsdd/summary/ exists, its step 7 renders the checkpoint page.

#[0.8.0] - 2026-08-03 (never released; ships in 0.10.0)

A consolidation, not a delta. spec/hsdd-spec-v0_8.md is a single standalone specification absorbing v0.3 through v0.7.1 and the tool-free half of the shelved vNext exploration. The delta series remains in spec/ as history; nothing requires reading it. The delta format is retired for major revisions.

Two new chapters carry the release's substance, both from one observation: the tree does not complete — phases complete, so after the first change every project is brownfield. Greenfield is a three-month bootstrap; the rest of a system's life is the steady state.

Design: docs/superpowers/specs/2026-07-29-v0_8-consolidation-brownfield-design.md. Acceptance record: review/hsdd-v0_8-acceptance.md (13/13 criteria PASS).

#Added

  • Chapter 6 — Entry B: Brownfield Adoption. A codebase that already exists becomes a structural peer of the greenfield entry, not a special case. hsdd-adopt (forthcoming skill) extracts seams by bundled script, proposes a shallow tree on the seams that exist, and writes as-built node specs carrying an ## Observed surface section stamped with the extraction SHA — with unknown: lines required, because a node with no unknowns is a node nobody looked at. It stops there: no decomposition below what the first change needs, and never a proposal to refactor the system into a nicer tree. Adoption cost scales with seam count, not LOC.
  • Chapter 11 — Steady State: Change Intake. hsdd-intake (forthcoming skill) routes an incoming change request into the existing tree — local / cross-node / new-capability / structural — and writes the routing decision before the handoff. The load-bearing rule: a PRD is never a root; there is one tree and it is the system's. Intake records accumulate, dated and never superseded — the rule that replaces "wipe hsdd/ and rebuild." Includes phase-plan append mode, spec graft mode, node retirement, collision serialization across open intakes, and a legal bypass for production incidents (hotfix → backfill finding → retro phase, escalating if unclosed across two checkpoints).
  • Chapter 14 (chapter 15 in the current specification) — Upgrading and Compatibility. v0.8.0 is additive; the vehicle is checkpoint's existing adoption run. The one rule with teeth — stable contracts need executable validation — is grandfathered and discharged on touch: the set closes at upgrade, each contract gains fixtures only when a phase next touches it, and the remaining count is reported every checkpoint and can only fall.
  • Adopted contracts start at v0 with a required ## Observed completeness caveat. v0 is a permanent property, not a waypoint; v0 → v1 is the contract-level adoption exit, taken only on redesign.
  • Per-contract-version compatibility: policy — additive-only (the Protobuf discipline, claimable only if existing fixtures still pass), versioned (default), frozen — plus the retired status, external_consumers, and a live-consumer retirement finding.
  • Per-campaign milestone documents, sealed when every gate is green and moved to management/archive/; sealing is evidence-backed, never declared.
  • From vNext: executable validation for stable, both gates running the contract, integration nodes, the ## Learnings loop dispositioned at the gate, mid-phase contract renegotiation, the unified Phase Equivalent, phase ordering as a named policy (interfaces-first default), the Team field, and the ## Metrics block.

#Changed

  • Honest claims (chapter 15, now chapter 16, mirrored in the README): context isolation is probabilistic, not enforced — the defense is prose and structure, pressure-tested and holding, not a mechanism. HSDD bounds per-session token cost; it does not reduce the total.
  • The settled-decisions table gains a required provenance column (field-tested / pressure-tested / reasoned-only) so new material cannot inherit credibility from tested material. Most of what this release adds is reasoned-only, and the document says so.
  • README and users guide: the reading path collapses to one specification, the skill table grows to ten, and the guide gains a brownfield walkthrough (adopt → intake → promote).

#Not included

  • No hsdd CLI. No context, lint, status, rename, check-scope, or template. Mechanical invariants stay prose- and structure-enforced, on the 0.6.0 pressure-campaign evidence. Scripts are permitted only under one boundary: bundled with a new skill, never changing how an existing skill behaves. The mechanization line stays on the shelf as a later candidate.
  • No hsdd-review skill, no multi-team enforcement, no back-application of v0.8.0 rules to existing artifacts, and no support for projects below 0.6.1 (upgrade to 0.6.1 first).
  • Skill files are unchanged in this release. hsdd-adopt and hsdd-intake and the amendments to the existing eight follow in a separate cycle, after this specification is approved.

#[0.7.1] - 2026-08-01

#Changed

  • hsdd-checkpoint execution-plan shape — three structural anchors for the human-facing surface, no new invariants:
    • "Copy-paste prompts with validation" generalizes to Step details: every step gets exactly one detail block. 🤖/🤝 steps keep the exact prompt + Validate: line; 👤 steps gain a briefing (Why / Do / Done when) — one checkbox per action, each naming its concrete target. Table cells shrink to a one-sentence summary: the cell indexes, the block instructs.
    • New required Plan graph section: one Mermaid flowchart (load-bearing syncs as junctions, step batches in lane subgraphs, edges from the Depends column), derived from the tables and regenerated whole — when graph and tables disagree, the tables win. ~20-node ceiling; no per-phase charting; applies in scoped mode too.

#Migration (existing projects)

bash
mkdir -p hsdd/scripts
git mv docs/conventions.md hsdd/conventions.md
git mv docs/spec hsdd/spec
git mv docs/verify hsdd/verify        # if present
git mv contracts hsdd/contract

Then update the layout section of hsdd/conventions.md (or re-seed it from the template) and re-copy the bundled generator, since the old copy scans the old paths. Keeping the old layout is also fine: state it in the conventions file and the skills honor it.
